# Conventions – vibe-coding (plugin repository)
> Pointers, not copies. One owner per fact: the document named after the arrow.

- Integration branch: `plugin-vibe-coding` for this round (ahead of `main`, never pushed); `main` is the release branch the directory and installs read ← round request (User, 2026-10-25); README "Development"
- Slice branch: `slice-NN`, cut from the integration branch; worktree under `.claude/worktrees/slice-NN`, `.claude/worktrees/` in `.git/info/exclude` ← skill vibe-coding (new for this repository); work/session-hints.md
- Merge style: one squash commit per slice onto the integration branch, made in the main checkout; never push ← round request (User, 2026-10-25)
- Commit language and style: English; one-line subject in the present tense without a trailing period, prefixed by the part it changes when that helps ("vibe-coding: …", "slice-board: …", "intake.md: …"); releases as "vibe-coding 1.1.0: <headline>"; a body only when the why is not obvious ← git log
- Build: none (no compiled code); `python -m py_compile plugins/vibe-coding/skills/vibe-coding/scripts/*.py tests/*.py` stands in for it ← .github/workflows/validate.yml "Check scripts"
- Test: `python tests/markers_test.py`, `python tests/render_slices_test.py`, `python tests/loop_test.py` (the loop test needs bash and/or pwsh on PATH and takes about a minute; missing shells are skipped) ← README "Development", tests/loop_test.py docstring
- Lint / format check: `claude plugin validate --strict plugins/vibe-coding` (plugin) and `claude plugin validate .` (marketplace, not strict: slice-board carries no version on purpose, every commit is an update); `bash -n plugins/vibe-coding/skills/vibe-coding/assets/slice-loop.sh`; PowerShell parse `pwsh -NoProfile -Command "\$null = [scriptblock]::Create((Get-Content -Raw plugins/vibe-coding/skills/vibe-coding/assets/slice-loop.ps1))"` ← .github/workflows/validate.yml
- Baseline check (before every slice): `claude plugin validate --strict plugins/vibe-coding`, then `python tests/markers_test.py`, `python tests/render_slices_test.py`, `python tests/loop_test.py` – one command per line, never joined by a pipe ← derived from .github/workflows/validate.yml; run each command on its own and read its exit code (CLAUDE.md of the workspace, "Prüfbefehle nie mit `| tail` in eine `&&`-Kette")
- Checks for a slice: the baseline check; when a loop script changed, also `bash -n` and the PowerShell parse (above); when `plugin.json` or `SKILL.md` changed, also `claude plugin validate .`; the markers test is the privacy scan of the skill folder – extend it with the same regex over `work/` when round files changed. The only full suite is `tests/loop_test.py` (about a minute); it runs the fake `claude` in temporary folders, so two runs at once do not collide ← README "Development", tests/markers_test.py
- Full check chain (round close): the steps of .github/workflows/validate.yml in order – `claude plugin validate .` (marketplace, not strict: slice-board carries no version on purpose, every commit is an update; commit 8d59d22), `claude plugin validate --strict plugins/vibe-rebuild`, `… plugins/vibe-coding`; `skills-ref validate plugins/vibe-coding/skills/vibe-coding` (needs `pip install "skills-ref @ git+https://github.com/agentskills/agentskills.git#subdirectory=skills-ref"`; skipped locally when pip cannot reach it, then the CI run on `main` is the proof); `python -m py_compile …`; the renderer smoke test in `en` and `de`; `python tests/render_slices_test.py`; `python tests/markers_test.py`; `bash -n …slice-loop.sh`; the PowerShell parse; `python tests/loop_test.py` ← .github/workflows/validate.yml
- Decisions are recorded in: plugins/vibe-coding/CHANGELOG.md, one `## <version> – <date>` section per release with bold-led bullets (what changed and why, tests named); no ADR folder. The round record holds the rulings of a round ← plugins/vibe-coding/CHANGELOG.md, README "Development"
- Must change with a change: plugins/vibe-coding/CHANGELOG.md (bullet under the version in progress, `## 1.2.0 – <date>`); plugins/vibe-coding/README.md and the root README.md when user-visible behaviour changes (commands, loop options, files written, tests described); `tests/markers_test.py` when the command, the loop scripts or the templates gain a contract (marker, format, phrase); `version` in plugins/vibe-coding/.claude-plugin/plugin.json and `metadata.version` in SKILL.md once per release, by the release slice ← README "Development"
- Version of this round: 1.2.0 ← round request (User, 2026-10-25)
- Pull-request rule: no pull request per slice; `main` receives the integration branch when the round is done and the user releases it; CI runs on pushes to `main` and on pull requests (noted only) ← .github/workflows/validate.yml
- Language: everything English – skill files, references, README, changelog, tests, commit texts and the round files in `work/` ← repository rule (User, 2026-10-25); README
- Privacy rule for names in files: no personal names, decisions are recorded as "User, <date>"; no absolute paths, user or machine names, private mail addresses (`tests/markers_test.py` scans the skill folder for Windows and Unix home-directory paths and a well-known private mail domain) ← tests/markers_test.py, round request
