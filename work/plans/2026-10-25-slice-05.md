Round R01 (field lessons) · Slice 05 · Model opus · Deps: 04 (done) · Integration branch `plugin-vibe-coding` · Slice branch `slice-05` in `.claude/worktrees/slice-05`

## Goal
Both loop scripts squash finished branches one after another in the main checkout: they accept `SLICE-READY: NN`, squash the branch, commit with the message from `.slice-loop/slice-NN.msg`, tick Commit, remove the merged branch and its worktree, and stop with the file names on any conflict; `--merge` / `-Merge` runs that queue alone (F-01 queue, F-08 loop).

## Facts checked in a throw-away repository (decide the design)
- Two branches cut from the same base that tick **adjacent checklist rows** conflict on the second `git merge --squash` (git treats touching hunks as one). The parallel case therefore needs slice 06.
- `git reset --merge` after a conflicted `git merge --squash` leaves the tracked tree clean.
- `git branch -d slice-NN` **refuses** after a squash merge (the branch is no ancestor of HEAD); deleting needs `-D`.
- A worktree inside the repository shows as untracked unless `.claude/worktrees/` is excluded; this machine has `core.autocrlf=true`, so the test repositories set `core.autocrlf=false` locally.

## Assumptions (confirm on approval)
1. **One finishing path for both markers.** After a build turn the loop accepts `SLICE-DONE: NN` or `SLICE-READY: NN` (anything else stops as today). Then: row already done on the integration branch → done (the `SLICE-DONE` path, unchanged); otherwise the branch must be ready to merge and goes through the queue; neither → stop with "reported done or ready but not ticked". Sequential and parallel runs share this code. Recommendation: yes.
2. **Ready to merge** = the slice's row in `git show slice-NN:work/checklist.md` has at least one ☑ and no ☐ outside its last cell (Commit). The same check gates the build path and `--merge`. Recommendation: yes.
3. **Queue step**, in the main checkout (the loop's working directory, which `/slice` section 4 step 5 calls the parent of `git rev-parse --git-common-dir`): tracked tree clean (`git status --porcelain` empty; ignored files such as `.slice-loop/` do not count) → `git merge --squash slice-NN` → on a conflict `git reset --merge`, keep branch and worktree, stop with exit 1 naming `git diff --name-only --diff-filter=U` → tick the last ☐ of row NN in `work/checklist.md` (line endings kept) → `git add work/checklist.md` → `git commit -F .slice-loop/slice-NN.msg` → `is_done` check. The message file stays in `.slice-loop/` as part of the log. Recommendation: yes.
4. **Fallback message (F-08).** No message file → write `Slice NN: <name> (<source>)` from `work/_slices.json` to `.slice-loop/slice-NN.fallback.msg` and commit with `-F`; without a source the parentheses are left out. The bash reader takes text fields the way `slice_model` takes `model` (one helper `slice_field nr field`; `slice_model` uses it), so a name with an escaped quote is cut at the quote – noted, not handled. PowerShell reads them with `ConvertFrom-Json`. Recommendation: yes.
5. **Cleanup with `-D`.** After the squash commit: `git worktree remove <path>` without `--force` when `git worktree list --porcelain` shows a worktree on `slice-NN`, then `git branch -D slice-NN`. The slice file says `-d`, which always refuses after a squash; the squash commit the queue just made is the evidence that the branch is merged, and `/slice` allows removing the merged `slice-NN` branch and its worktree. A worktree that cannot be removed (untracked files, a junction) is reported, and its branch is kept with it; the slice still counts as done. Recommendation: yes.
6. **Parallel order.** Builds run side by side as today; the main process then waits for them in the order of the ready list and squashes each one as soon as it and the ones before it have finished. The slice file says "finishing order": true finishing order needs `wait -n -p` (bash 5.1), which the script's bash 4.4 floor does not give, and the list order is deterministic in both shells and in the test. Recommendation: yes.
7. **Parallel stops until slice 06.** Two ready slices built in parallel tick adjacent checklist rows, so the second squash conflicts in `work/checklist.md` and the loop stops with that file named and the branch kept. The parallel case of the loop test changes its expectation from "both land, round closes" to "first lands, second stops on `work/checklist.md`", with a comment that slice 06 restores it; slice 06 gets this as its first acceptance case (Deferred minors). Nothing is released between 05 and 06 (release is slice 07). The other option – pulling the tick union of slice 06 into this slice – mixes the two slices. Recommendation: accept the temporary stop.
8. **`--merge` / `-Merge`** runs before the open-round and `claude` checks (no session, works with a closed round): every local branch `slice-*`, lowest number first; done on the integration branch → skipped; ready → queued; not ready → reported and left; exit 0, or 1 on the first conflict. `.slice-loop/` and its exclude line are set up before it. Other options are ignored with `--merge`. Recommendation: yes.
9. **No lock in the queue.** The queue runs no test suite, so it takes no full-suite lock (slice 04's deferred question); two queue runners at once are not guarded beyond git's own `index.lock` – a merge-queue lock is a deferred minor. Recommendation: yes.
10. **Tests.** The vibe-coding profile of `tests/loop_test.py` runs in a real git repository (`git init -b main`, local test identity `loop-test <loop-test@example.invalid>`, `core.autocrlf=false`, `stub-calls.log` and `.claude/worktrees/` excluded). The fake claude, for this profile only: creates or reuses `.claude/worktrees/slice-NN` on `slice-NN`, ticks the row through Checks, adds `slice-NN.txt`, commits with `-F`, writes `.slice-loop/slice-NN.msg` (`Slice NN stub squash`) and prints `SLICE-READY: NN`; `STUB_NO_TICK`, `STUB_NO_MESSAGE` and `STUB_MARKER=done` (the old in-place tick plus `SLICE-DONE`) cover the other paths. Cases take an optional dict of git expectations after the outcome tuple (subjects since the initial commit, remaining `slice-*` branches, a phrase in the output, no claude call, prepared branches). The vibe-rebuild profile and its stub path are unchanged. `PWSH_FLAGS` gains `--merge` → `-Merge`. Recommendation: yes.
11. **Docs.** Script headers and usage lines name the option; CHANGELOG bullet under `## 1.2.0`; READMEs are slice 07. `.claude/commands/slice.md` and `.claude/scripts/` (the round-start copies) stay as they are until the round ends. Recommendation: yes.
